### Decisions locked (architecture-deferred items resolved)

- **AD-1 Framework: React Native + Expo (SDK 53+).** Considered Capacitor and Flutter. Picked RN for the FR-5 haptic-richness gap on iOS (Capacitor's plugin can't do the 200/400ms thinking rhythm without a custom native module; RN's `react-native-haptic-feedback` + `expo-haptics` covers it via CoreHaptics). Dart learning curve disqualified Flutter for a 6–8 week solo build where the UI is two buttons.
- **AD-2 iOS distribution: TestFlight via EAS Submit.** Ad-hoc was the runner-up; ruled out on UDID-per-device friction. Apple Developer $99/yr required either way.
- **AD-3 Memory log schema: SQLite, two tables (`objects`, `sightings`) + `usage_events`.** Normalized so FR-3 catalog entries can exist before any sighting and so the freshness-window query (`MAX(observed_at)`) is cheap with one index.
- **AD-4 Noun-phrase extractor: structured JSON from Gemini.** No client-side NLP. One model call returns both the Argentine-Spanish narration and a parallel `objects` JSON array with canonical names. OpenRouter's `response_format: { type: 'json_object' }` is the wire format, keeping AD-1's gateway-agnostic posture (NFR-11).
- **AD-5 Snapshot cache: LRU, 50 entries or 200MB, app-private storage.** Defaults; sideload-tunable in `src/config.ts`.
- **AD-6 Telemetry: local SQLite `usage_events` + 10-second-hold debug screen.** No cloud analytics. Same gesture family as the FR-3 setup screen (5s hold) — different timings. Charly inspects + exports JSON locally.
- **Library lock for v0.9** (AD-1 detail): `expo-camera`, `expo-speech`, `@react-native-voice/voice` (Expo config plugin) for STT, `expo-haptics` + `react-native-haptic-feedback` for the two halves of FR-5, `expo-sqlite`, native `fetch`, React Context + `useReducer` for state. No Redux.
- **OpenRouter request shape locked.** Model id `google/gemini-2.5-flash`, `response_format: { type: 'json_object' }`, `temperature: 0.3`, `max_tokens: 400`. Conventional `HTTP-Referer` + `X-Title` headers set so the spend line is identifiable.
- **Cross-platform divergence isolated** to the `adapters/` layer. Domain layer is platform-agnostic; this is the structural commitment that lets one codebase serve both Android (dad) and iOS (Charly) without `Platform.OS` checks in services.
- **Test strategy: Jest unit tests on services + manual smoke testing.** No Detox/Maestro E2E for v0.9 — premature at this scope. No crash reporting SDK; privacy-first per NFR-5.
- **Suggested story slicing in §12** — ~26 stories across the six PRD epics. Sprint planning sequences them.

### Live-doc verification — 2026-05-26 (rev 2)

- **Trigger:** Charly flagged that the rev-1 draft did not verify versions against live docs — pointed to my own [feedback memory about researching current docs](../../../../../.claude/projects/-Users-carlosbernardi-Documents-Claude-Work-Image-Recognition-App/memory/feedback_research_current_docs.md). I had relied on training-data memory (Jan 2026 cutoff) for a doc dated May 2026. Fair call.
- **Method:** Delegated verification of 12 stack items to a research subagent with WebFetch/WebSearch access. All findings cite primary doc URLs now embedded inline in the architecture.
- **Findings — three actual stack changes:**
  1. **Expo SDK 53 → 56** (released 2026-05-21, 5 days before this doc). RN 0.85, React 19.2 paired. SDK 53 is already EOL in Expo Go. New Architecture (Fabric/TurboModules) is mandatory — legacy bridge permanently disabled in RN 0.82.
  2. **STT library swap:** `@react-native-voice/voice` was **archived on 2026-01-31** with an explicit deprecation banner pointing to **`expo-speech-recognition` (jamsch)**. Switched. The new library is Expo-config-plugin friendly and currently maintained (v56.0.0 released 2026-05-17).
  3. **expo-file-system API migration:** SDK 54 swapped the default export to the new class-based API (`File`, `Directory`, `Paths`). `FileSystem.documentDirectory` is now in `expo-file-system/legacy` and scheduled for removal. v0.9 must write to the new API from day one to avoid rewriting a few weeks in.
- **Findings — confirmations (no change needed):**
  - `expo-camera`'s `CameraView` API is still canonical.
  - `expo-speech` still supports `rate` and BCP-47 locales; runtime voice availability is what's actually variable.
  - `expo-haptics` and `react-native-haptic-feedback` are both current; mkuczera's library got a 2026 rewrite with `CHHapticEngine` + AHAP, which is even better for the FR-5 rhythmic pulse.
  - `expo-sqlite` modern API (`useSQLiteContext`, `PRAGMA user_version`) is current.
  - EAS Free tier (15 iOS + 15 Android builds/mo) is sufficient for MVP.
  - OpenRouter endpoint, `response_format: { type: 'json_object' }`, and `HTTP-Referer` + `X-Title` header convention all still correct.
  - `google/gemini-2.5-flash` is still listed and is the right "cheapest SOTA multimodal" pick for low-volume vision. Gemini 3.5 Flash GA'd 2026-05-19 but is 5× the cost for capabilities (agentic/coding) we don't need — explicitly ruled out.
  - Apple Developer Program still $99/yr.
- **New finding — runtime locale availability:** `es-AR` is a valid BCP-47 tag everywhere, but actual TTS *voice* availability on Android depends on the installed Google TTS voice pack, and STT locale availability is device-dependent. Adapter falls back to `es-419` (LatAm neutral) or `es-MX` if `es-AR` isn't installed. V3 validation now explicitly probes this — see updated §10.
- **Notable additions to architecture:**
  - Cost-A/B toggle: `MODEL_ID_CHEAP = 'google/gemini-2.5-flash-lite'` ($0.10/$0.40 per 1M) added to `src/config.ts` for the brief's cost-optimization A/B. Enables the path without a code rewrite.
  - Dev-client note: Expo Go can't bundle the haptic / STT native modules, so EAS dev-client build is required once per platform up front.
