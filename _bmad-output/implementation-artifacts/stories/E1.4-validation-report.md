## 1. Hindsight observations (cross-cutting from Sprint 1)

These came up during Sprint 1 implementation and should propagate into any adapter story before dev:

- **`expo install` not `npm install`** for Expo-managed deps — keeps SDK 56 compat. ✓ E1.4 already uses `npx expo install expo-speech-recognition`.
- **Jest can't load Expo native modules at module init** — `expo-asset` transitive bombs the test runner. Must `jest.mock(...)` the native module at the top of the test file. **The E1.4 test spec doesn't mention this.** Same fix that E1.7 and E1.3 used.
- **`@types/jest` + `tsconfig.types: ["jest"]`** required for `describe/test/expect` to type-check under `moduleResolution: bundler`. Already in the project from E1.8.
- **TypeScript 6.0 deprecated `baseUrl`** — `paths` is enough. Project's tsconfig is already correct.
- **React-component testing (`@testing-library/react-native`)** has a React 19.2.6 peer requirement that conflicts with SDK 56's React 19.2.3. Skip RN component tests for v0.9; focus on pure logic + adapter mocks. **Affects E1.4: no component tests — adapter only.**
- **ESLint flat config + the "no Spanish outside CopyModule" rule** is active. STT adapter must not embed Spanish strings — permission rationales go in `app.json` plugin config (build-time read, not source). The E1.4 plan already does this.

## 4. Acceptance Criteria — deep pass

### AC1.4.1 — `listen` / `abort` shape

OK. The Result<string, STTError> signature matches the established adapter convention (E1.3 TTS, E1.5 camera).

### AC1.4.2 — Locale fallback chain identical to TTS (E1.3)

**OK + NIT.** Pattern is right. Subtle gap: E1.3's TTS adapter falls back to `CONFIG.TTS_LOCALE` (es-AR) on probe failure; E1.4 returns `err('no_locale')` instead. That's *correct* — STT can't speak when it can't understand the locale at all — but it means a fresh-install on a phone with no Spanish recognizer support produces a guaranteed failure rather than degraded behavior. **Fix:** make the spec explicit that this is intentional; STT requires the engine to claim support, whereas TTS will just speak in whatever voice is closest.

### AC1.4.3 — STTError taxonomy

OK. Six error codes; matches the gentle-question copy mapping at the consumer (E3.2).

### AC1.4.4 — V3 fixture file

**NIT.** Fixture mentions "20 utterances" but has 20 entries already-numbered. Good. **Improvement:** clarify in §6 (Definition of Done) whether the fixture file gets created in this story or is just *referenced* (Charly fills it in during V3). Right now it's ambiguous — the AC says "lists 20 Argentine-Spanish utterances" which could mean the template file is created blank-of-results.

**Fix:** AC1.4.4 should specify "the fixture file exists in `docs/validation/stt-fixture.md` with the 20 prompts; result checkboxes are left empty for Charly to fill during V3."

### AC1.4.5 — Unit test mocking event lifecycle

**BLOCKER.** The test spec says "mocks `expo-speech-recognition`'s event lifecycle (`start` → `result` → `end`)" but the adapter uses **`useSpeechRecognitionEvent`** which is a React hook. Hooks can't be called from inside a Promise constructor — they require a component render context. The spec's own §4.2 note flags this: *"Note: `useSpeechRecognitionEvent` is a hook in the library docs — verify at impl time whether plain `.addListener` works in this non-component context."*

This is a real implementation gap. The adapter shape in §4.2 will NOT work as written. **Fix:** revise §4.2 to use the imperative `.addListener(eventName, handler)` API that returns a subscription handle (or whatever the library actually exposes for non-React contexts). If the library only exposes a hook, the adapter pattern needs to invert — services subscribe via a hook in a hosting component, similar to how `CameraHost.tsx` works in E1.5.

### AC1.4.6 — `abort()` interrupts in-flight `listen()`

**NIT.** Current spec says abort "rejects with `'timeout'` or resolves with partial transcript (consumer's call)." That's actually adapter-level ambiguity, not consumer-level. **Fix:** pick one. Recommended: `abort()` causes `listen()` to resolve with `err('timeout')` (cleaner contract than partial-transcript magic).

## 5. Technical Approach

### §4.1 — Permissions in app.json

**NIT.** Two permission strings (`microphonePermission` and `speechRecognitionPermission`) — both in Spanish. Good. **But:** these are duplicated knowledge with the COPY module if we ever add `COPY.permissions.mic`. Since `app.json` is build-time-only and can't reference TS, we accept the duplication; **fix:** add a note that the duplication is intentional and should be kept in sync manually (or via a build script in a later story).

### §4.2 — Adapter implementation

**BLOCKER.** Per AC1.4.5 above. The hook-based listener pattern doesn't work in a Promise constructor outside a React component. Rewrite using `.addListener` or a hosting-component pattern.

Also: the example code calls `subError` before it's declared in the source order (`subResult.remove(); subEnd.remove(); subError.remove();`). TypeScript will catch this at compile time as a temporal dead zone use-before-declaration. **Fix:** declare all three subscriptions before the handlers reference each other, or wrap the trio in a single cleanup helper.
