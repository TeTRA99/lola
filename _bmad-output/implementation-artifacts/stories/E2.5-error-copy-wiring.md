# E2.5 — Confidence + network error copy wiring

> **User story:** As dad, I want Lola to say a gentle question when she can't see clearly or doesn't have signal, so that I'm never confronted with a technical failure message.

## 1. Context

DescribeService (E2.2) already routes errors to specific COPY lines, but the wiring is implicit — driven by `switch (err.error)` matching error codes to message keys. This story makes the mapping explicit, testable, and audits each FR-6.4 copy line has a reachable path.

## 3. Acceptance Criteria

- [ ] **AC2.5.1** — `app/src/services/errorCopy.ts` exports a pure `errorCopyFor(errorKind: ErrorKind): keyof COPY['errors']` function. `ErrorKind` is the union of all known service / adapter / gateway error codes.
- [ ] **AC2.5.2** — Five FR-6.4 copy lines are each reachable from at least one error kind: low_confidence → `lowConfidence`, network → `noNetwork`, permission_denied (camera) → `cameraPermission`, permission_denied (mic) → `micPermission`, everything else → `generic`.
- [ ] **AC2.5.3** — DescribeService and (later) AskService delegate to `errorCopyFor` instead of inline switch statements. Reduces drift risk.
- [ ] **AC2.5.4** — Unit test exhaustively asserts every `ErrorKind` value maps to a defined COPY key (no missing branches).
- [ ] **AC2.5.5** — Confidence threshold constant: `CONFIG.CONFIDENCE_THRESHOLD` (0.70) already exists. Heuristic detection (empty objects + gentle-question prefix) already lives in DescribeService; this story refactors the heuristic into a named `isLowConfidenceResponse(response)` helper in `errorCopy.ts` for reuse by AskService later.

## 4. Technical Approach

### 4.1 errorCopy module

`app/src/services/errorCopy.ts`:

```typescript
import { COPY } from './CopyModule';
import type { LolaResponse } from '@/gateways/openrouter';

export type ErrorKind =
  | 'low_confidence'
  | 'network'
  | 'parse_fail'
  | 'permission_denied_camera'
  | 'permission_denied_mic'
  | 'no_camera'
  | 'no_speech'
  | 'timeout'
  | 'no_locale'
  | 'engine_unavailable'
  | 'auth'
  | 'rate_limit'
  | 'unknown';

const MAP: Record<ErrorKind, keyof typeof COPY.errors> = {
  low_confidence: 'lowConfidence',
  network: 'noNetwork',
  permission_denied_camera: 'cameraPermission',
  permission_denied_mic: 'micPermission',
  parse_fail: 'generic',
  no_camera: 'generic',
  no_speech: 'generic',
  timeout: 'generic',
  no_locale: 'generic',
  engine_unavailable: 'generic',
  auth: 'generic',
  rate_limit: 'generic',
  unknown: 'generic',
};

export function errorCopyFor(kind: ErrorKind): string {
  return COPY.errors[MAP[kind]];
}

const LOW_CONFIDENCE_PREFIXES = ['No estoy segura', 'No tengo', 'No puedo'];

export function isLowConfidenceResponse(resp: LolaResponse): boolean {
  return resp.objects.length === 0 &&
    LOW_CONFIDENCE_PREFIXES.some(p => resp.narration.startsWith(p));
}
```

### 4.2 DescribeService refactor

Replace inline copy lookups with `errorCopyFor(...)` calls. Same for `isLowConfidenceResponse(resp)` — pulled out of the inline heuristic.

The camera permission_denied case maps to `permission_denied_camera` (this story's first integration; AskService gets `permission_denied_mic` in E3.x).

## 7. Risks

- **Exhaustive ErrorKind:** if a new adapter introduces an error code not in `ErrorKind`, TS will complain at the consumer. **Good** — drives explicit decision about which COPY line it maps to.
- **AskService isn't refactored here** — when E3.2 lands, it gets the same treatment. The duplication risk is bounded; flag in code review.
