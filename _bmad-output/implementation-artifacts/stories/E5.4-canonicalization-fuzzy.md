# E5.4 — Canonicalization fuzzy match

> **As dad,** I want to say "¿viste mi cepillo?" and have Lola find it even though the model originally logged it as "el cepillo de Charly Sr.", so that I can use my own words.

## 1. Context

The model's per-snapshot canonical names are non-deterministic (`"cepillo"`, `"cepillo_de_dientes"`, `"cepillo_del_papa"`). Dad's utterance comes in as Spanish prose (`"cepillo"`, `"mi cepillo"`). The matcher needs to bridge both into a single object_id from the SQLite catalog.

This story is the resolver — it doesn't query for sightings directly (that's E5.2). It answers: "given the noun dad said, which object_id is most likely?"

## 2. References

- **PRD:** [FR-4 canonicalization (AC4.3)](../../../planning-artifacts/prds/prd-Lola-2026-05-26/prd.md#fr-4-where-is-x-passive-memory-log)

## 3. Acceptance Criteria

- [ ] **AC5.4.1** — `MemoryService.resolveObjectFromUtterance(noun: string): Promise<number | null>` — given dad's noun extracted by E3.1's utterance router, return the best matching `object_id` from the SQLite `objects` table.
- [ ] **AC5.4.2** — Match precedence (each step queries SQLite once):
  1. Exact canonical match (`canonical_name = canonicalize(noun)`).
  2. Exact display_name match (case-insensitive).
  3. Display_name LIKE %noun% (substring, case-insensitive).
  4. Description LIKE %noun% (substring).
  Returns the first hit's id; null if all four miss.
- [ ] **AC5.4.3** — Noun cleanup: strip leading possessives (`mi`, `tu`, `el`, `la`, `los`, `las`) before canonicalizing. So `"mi cepillo"` → canonicalize → `cepillo`.
- [ ] **AC5.4.4** — Unit tests cover: exact canonical, display match, possessive strip, fuzzy substring, miss case, and a "multiple matches" scenario (returns whichever the SQL returns first per precedence).

## 4. Technical Approach

`app/src/services/MemoryService.ts` extends with:

```typescript
import { canonicalize } from './OnboardingService';

const POSSESSIVE_RE = /^(mi|tu|su|el|la|los|las)\s+/i;

function stripPossessive(s: string): string {
  return s.replace(POSSESSIVE_RE, '').trim();
}

export async function resolveObjectFromUtterance(noun: string): Promise<number | null> {
  const cleaned = stripPossessive(noun);
  const canonical = canonicalize(cleaned);
  const db = await getDb();

  // 1. exact canonical
  const exact = await db.getFirstAsync<{ id: number }>(
    'SELECT id FROM objects WHERE canonical_name = ? LIMIT 1', [canonical],
  );
  if (exact) return exact.id;

  // 2. exact display
  const disp = await db.getFirstAsync<{ id: number }>(
    'SELECT id FROM objects WHERE LOWER(display_name) = LOWER(?) LIMIT 1', [cleaned],
  );
  if (disp) return disp.id;

  // 3. display substring
  const dispSub = await db.getFirstAsync<{ id: number }>(
    'SELECT id FROM objects WHERE LOWER(display_name) LIKE LOWER(?) LIMIT 1',
    [`%${cleaned}%`],
  );
  if (dispSub) return dispSub.id;

  // 4. description substring
  const descSub = await db.getFirstAsync<{ id: number }>(
    'SELECT id FROM objects WHERE description IS NOT NULL AND LOWER(description) LIKE LOWER(?) LIMIT 1',
    [`%${cleaned}%`],
  );
  if (descSub) return descSub.id;

  return null;
}
```

## 6. Risks

- **SQL LIKE on description does full table scan.** At <100 catalog rows this is trivial. Add FTS5 in v1.0 if dad tags hundreds of objects.
- **Stemming gap:** `"cepillos"` (plural) won't match `"cepillo"` via the canonical step. Acceptable for v0.9; the substring fallback catches most plurals.
