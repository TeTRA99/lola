# E1.3 — TTS adapter + greeting integration

> **User story:** As dad, I want Lola to say *"Hola, listo cuando quieras"* in Argentine Spanish every time I open the app, so that the companion frame establishes itself before I do anything.

## 1. Context

This is the first dad-facing behavior to ship — even though there's no Home screen yet, the *splash → greeting* moment is the first thing dad will experience at sideload time, and it's also the smallest end-to-end test of the audio pipeline. Locking it now means every subsequent story can call `tts.speak(...)` with confidence.

This is one of three risk-flagged stories in Sprint 1 (the others are E1.4 STT and E1.6 Haptic). The risk is **TTS voice availability** on dad's Android phone — V3 validation surfaces whether the `es-AR` voice is installed; this story builds the fallback policy.

## 3. Acceptance Criteria

- [ ] **AC1.3.1** — `app/src/adapters/tts.ts` exports `speak(text: string, opts?: SpeakOptions): Promise<Result<void, TTSError>>` and `stop(): void`. `SpeakOptions` allows overriding rate; default is `CONFIG.TTS_RATE`.
- [ ] **AC1.3.2** — Default locale on `speak` is `CONFIG.TTS_LOCALE` (`es-AR`). If the device doesn't have `es-AR` voice installed, the adapter probes `Speech.getAvailableVoicesAsync()` once at boot and picks the first available from `[CONFIG.TTS_LOCALE, ...CONFIG.TTS_LOCALE_FALLBACKS]`. Decision is logged once via `console.log` (will route to `usage_events` table once E1.7 exists — note in code with TODO comment).
- [ ] **AC1.3.3** — Rate is `CONFIG.TTS_RATE` (0.85) by default. Faster/slower overrides accepted via `opts.rate`.
- [ ] **AC1.3.4** — `app/src/screens/LaunchSplash.tsx` exists as a temporary 800ms splash that calls `tts.speak(COPY.greeting)` on mount and then dismisses (via callback or navigation — final routing happens in E2.3/E4.1; for this story, a placeholder dismissal is fine).
- [ ] **AC1.3.5** — On a fresh `expo start` boot on Charly's iOS device, the greeting plays at a recognizable Argentine speed. **Manual verification step**, recorded in the dev story commit note.
- [ ] **AC1.3.6** — All errors are returned as `Result.err(...)`, never thrown. The `TTSError` type is `'no_voice_available' | 'engine_unavailable' | 'unknown'`.
- [ ] **AC1.3.7** — Unit test `app/src/adapters/__tests__/tts.test.ts` mocks `expo-speech` and verifies: (a) `speak('hello')` calls `Speech.speak` with `{ language: 'es-AR', rate: 0.85 }` by default; (b) when `getAvailableVoicesAsync` returns no `es-AR` but does return `es-MX`, subsequent `speak` calls use `es-MX`; (c) `stop()` calls `Speech.stop()`.

### 4.2 Adapter shape

`app/src/adapters/tts.ts`:

```typescript
import * as Speech from 'expo-speech';
import { CONFIG } from '@/config';
import { Result, ok, err } from '@/utils/result';   // skeleton from E1.8 — for now, define inline TODO

export type TTSError = 'no_voice_available' | 'engine_unavailable' | 'unknown';
export type SpeakOptions = { rate?: number };

let resolvedLocale: string | null = null;

async function resolveLocale(): Promise<string> {
  if (resolvedLocale) return resolvedLocale;
  try {
    const voices = await Speech.getAvailableVoicesAsync();
    const installed = new Set(voices.map(v => v.language));
    const candidates = [CONFIG.TTS_LOCALE, ...CONFIG.TTS_LOCALE_FALLBACKS];
    resolvedLocale = candidates.find(loc => installed.has(loc)) ?? CONFIG.TTS_LOCALE;
    if (resolvedLocale !== CONFIG.TTS_LOCALE) {
      // TODO(E1.7+): write usage_events row { action: 'tts_locale_fallback', from: TTS_LOCALE, to: resolvedLocale }
      console.warn('[tts] es-AR not installed, falling back to', resolvedLocale);
    }
  } catch {
    resolvedLocale = CONFIG.TTS_LOCALE;
  }
  return resolvedLocale;
}

export async function speak(text: string, opts: SpeakOptions = {}): Promise<Result<void, TTSError>> {
  const language = await resolveLocale();
  try {
    Speech.speak(text, { language, rate: opts.rate ?? CONFIG.TTS_RATE });
    return ok(undefined);
  } catch (e) {
    return err('unknown');
  }
}

export function stop(): void {
  Speech.stop();
}
```

### 4.3 LaunchSplash placeholder

`app/src/screens/LaunchSplash.tsx`:

```typescript
import { useEffect } from 'react';
import { View, Text, StyleSheet } from 'react-native';
import { speak } from '@/adapters/tts';
import { COPY } from '@/services/CopyModule';

export function LaunchSplash({ onDone }: { onDone: () => void }) {
  useEffect(() => {
    speak(COPY.greeting);
    const t = setTimeout(onDone, 800);
    return () => clearTimeout(t);
  }, [onDone]);

  return (
    <View style={styles.root}>
      <Text style={styles.brand}>Lola</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  root: { flex: 1, backgroundColor: '#000', justifyContent: 'center', alignItems: 'center' },
  brand: { color: '#fff', fontSize: 64, fontWeight: '700' },
});
```

## 8. Risks

- **`es-AR` voice not installed on dad's Android.** V3 catches it; adapter falls back to `es-419` or `es-MX`. Worst case the brand voice differs slightly from Charly's iOS — acceptable for v0.9; NFR-9 fallback to ElevenLabs is the v1.0 escalation.
- **Web target (`expo start --web`) has different TTS behavior.** Not in scope — v0.9 is Android + iOS only. If `expo start --web` is used for quick iteration, accept that the greeting may not play; don't write web-specific shims.
- **`Speech.speak` is fire-and-forget.** Returns void synchronously; the Promise resolution in our wrapper isn't "speech complete," just "speech started." That's fine for the greeting (no caller awaits completion) but a future story may need `Speech.speak({ onDone })` callbacks. Note in code, address when needed.
