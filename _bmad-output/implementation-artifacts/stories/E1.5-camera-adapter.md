# E1.5 — Camera adapter

> **User story:** As a developer, I want a snapshot-only camera adapter, so that Describe and Ask can capture a single image without exposing video or live-preview surface to dad.

## 1. Context

PRD FR-1/FR-2 are snapshot-based (NOT continuous vision — that's a v3+ wearable concern per the brief's Out-of-Scope). This adapter is the single capture primitive. Three consumers: DescribeService (E2.2), AskService (E3.2), OnboardingService for reference photos (E4.3).

### 4.3 Adapter shape

`app/src/adapters/camera.ts`:

```typescript
import { CameraView, useCameraPermissions } from 'expo-camera';
import { Result, ok, err } from '@/utils/result';

export type CameraError = 'permission_denied' | 'no_camera' | 'capture_failed' | 'unknown';
export type Snapshot = { uri: string; base64: string; width: number; height: number };

// CameraView is a React component; the adapter exposes a ref-based imperative API for services.
// Strategy: services mount a hidden CameraView (size 1×1, off-screen) via React Context; the
// adapter holds a ref to it and triggers takePictureAsync().

let cameraRef: any = null;

export function _registerCameraRef(ref: any) { cameraRef = ref; }

export async function captureSnapshot(): Promise<Result<Snapshot, CameraError>> {
  if (!cameraRef) return err('no_camera');
  try {
    const photo = await cameraRef.takePictureAsync({
      base64: true,
      quality: 0.85,
      skipProcessing: false,
      // resize: handled by expo-camera's internal scaler or via expo-image-manipulator post-capture
    });
    if (!photo || !photo.base64) return err('capture_failed');
    // If photo is larger than 1024px on the longer edge, resize via expo-image-manipulator.
    return ok({ uri: photo.uri, base64: photo.base64, width: photo.width, height: photo.height });
  } catch (e: any) {
    if (String(e?.message ?? '').includes('permission')) return err('permission_denied');
    return err('unknown');
  }
}
```

The hidden-CameraView pattern is intentional — dad never sees a viewfinder. Two-button screen → tap → instant snapshot.

### 4.4 Hidden CameraView mount

`app/src/screens/HomeScreen.tsx` (placeholder; full screen comes in E2.3/E3.3) mounts a 1×1 invisible CameraView and registers its ref via `_registerCameraRef`. Future stories can move this to a Context provider if multiple screens need the camera.

### 4.5 Resize policy

If `expo-camera`'s `takePictureAsync` returns >1024px on the longer edge, post-process with `expo-image-manipulator`:

```bash
npx expo install expo-image-manipulator
```

```typescript
import { manipulateAsync, SaveFormat } from 'expo-image-manipulator';
// after takePictureAsync:
const longer = Math.max(photo.width, photo.height);
if (longer > 1024) {
  const ratio = 1024 / longer;
  const resized = await manipulateAsync(
    photo.uri,
    [{ resize: { width: photo.width * ratio, height: photo.height * ratio } }],
    { compress: 0.85, format: SaveFormat.JPEG, base64: true }
  );
  return ok({ uri: resized.uri, base64: resized.base64!, width: resized.width, height: resized.height });
}
```

## 8. Risks

- **CameraView mount order vs. permission grant.** If the hidden CameraView mounts before permission is granted, it shows a "no camera" black surface. Handle: don't mount until `useCameraPermissions` granted; gate the entire HomeScreen behind a permission-request flow (deferred to E2.5 error-copy wiring).
- **Dev-only CameraTestScreen leaking to production builds.** Guard with `if (!__DEV__) return null;` at the screen's root, AND exclude from any route table in production. Code review check.
- **Base64 payload size.** A 1024×1024 JPEG @ 0.85 quality is ~150-300KB. Base64 inflates ~33%. OpenRouter accepts it; not a problem at one-user volume but worth knowing for cost projections.
