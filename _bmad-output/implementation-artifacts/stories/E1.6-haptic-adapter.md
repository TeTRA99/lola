# E1.6 — Haptic adapter with all five FR-5 patterns

> **User story:** As dad, I want to feel what Lola is doing at each step without listening for it, so that the rhythm of the interaction is comprehensible non-visually.

## 1. Context

The largest single Sprint 2 story (L, 1–2 days). FR-5's five-pattern Heartbeat is what gives dad real-time non-visual feedback about the system's state during Describe / Ask flows. The architecture deliberately picked RN + Expo over Capacitor for this reason — Capacitor's iOS haptic plugin only does basic impacts, not the 200/400ms rhythmic *thinking* pulse FR-5 specifies.

Two libraries are required (verified in [AD-1](../../../planning-artifacts/architecture/architecture-Lola-2026-05-26/architecture.md#ad-1-framework--react-native--expo)):
- `expo-haptics` — simple impacts + notifications on both platforms.
- `react-native-haptic-feedback` (mkuczera) — CHHapticEngine on iOS for the rhythmic pulse via AHAP patterns.

## 3. Acceptance Criteria

- [ ] **AC1.6.1** — `app/src/adapters/haptics.ts` exports `fire(pattern: HapticPattern): void` and `stop(): void` (latter cancels any running rhythmic pulse). `HapticPattern` enum: `'looking' | 'thinking_start' | 'thinking_stop' | 'answer_ready' | 'listening_start' | 'listening_stop' | 'error'`.
- [ ] **AC1.6.2** — Pattern timing matches `CONFIG` exactly:
  - `looking` = single tap, `HEARTBEAT_LOOKING_MS` (50ms).
  - `thinking_start` = start rhythmic pulse: `HEARTBEAT_THINKING_ON_MS` (200ms on) / `HEARTBEAT_THINKING_OFF_MS` (400ms off), repeating until `thinking_stop` or any other pattern.
  - `thinking_stop` = end the rhythmic pulse, no haptic.
  - `answer_ready` = double tap per `HEARTBEAT_ANSWER_READY` (`[50, 100, 50]`).
  - `listening_start`, `listening_stop` = soft single taps (lighter than `looking`).
  - `error` = long soft pulse `HEARTBEAT_ERROR_MS` (600ms).
- [ ] **AC1.6.3** — Library division: one-shot patterns (`looking`, `listening_start`, `listening_stop`, `answer_ready`'s individual taps, the `error` tail) use `expo-haptics` impact/selection APIs on both platforms. Rhythmic / multi-element patterns (`thinking_start`, `answer_ready`'s timed double-tap) use `react-native-haptic-feedback` for cross-platform pattern delivery. **No raw `Vibrator.vibrate(pattern[])` direct calls** — go through the library so platform branching stays inside one place.
- [ ] **AC1.6.4** — *Thinking* rhythmic pulse: best-effort via `setInterval` triggering `expo-haptics` impacts at `HEARTBEAT_THINKING_ON_MS + HEARTBEAT_THINKING_OFF_MS` period. **If AC1.6.5 perception test fails on Charly's iOS device** (the perceived rhythm feels broken / gappy), escalate to `react-native-haptic-feedback` AHAP custom pattern (`trigger('customPattern', { hapticPattern: AHAP_THINKING })`). AHAP JSON is sideload-tunable in code. iOS-only escalation; Android setInterval is the production path either way. **AC5.3:** `answer_ready` fires even when device is in Do Not Disturb (user-initiated, not a notification).
- [ ] **AC1.6.5** — Between `thinking_start` and `thinking_stop`, no silent gaps >250ms (architecture §4.3). The pulse rhythm must produce a "thinking" felt-rhythm continuously.
- [ ] **AC1.6.6** — Patterns are distinguishable by hand on **both** Charly's iOS device and a representative Android phone. **Manual verification step**, recorded in dev story commit notes.
- [ ] **AC1.6.7** — A dev-only `HapticTestScreen.tsx` (behind debug flag, removed from production builds) exposes a button per pattern for manual sideload-time tuning.
- [ ] **AC1.6.8** — Unit test `app/src/adapters/__tests__/haptics.test.ts` mocks both libraries and verifies that each pattern dispatches the expected sequence of mock calls.

### 4.2 Adapter shape

`app/src/adapters/haptics.ts`:

```typescript
import * as Haptics from 'expo-haptics';
import ReactNativeHapticFeedback from 'react-native-haptic-feedback';
import { Platform } from 'react-native';
import { CONFIG } from '@/config';

export type HapticPattern =
  | 'looking' | 'thinking_start' | 'thinking_stop'
  | 'answer_ready' | 'listening_start' | 'listening_stop'
  | 'error';

let thinkingTimer: ReturnType<typeof setInterval> | null = null;

function clearThinking() {
  if (thinkingTimer) { clearInterval(thinkingTimer); thinkingTimer = null; }
}

export function fire(pattern: HapticPattern): void {
  // Any pattern other than thinking_start cancels the rhythmic pulse.
  if (pattern !== 'thinking_start') clearThinking();

  switch (pattern) {
    case 'looking':
      Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Light);
      return;

    case 'listening_start':
    case 'listening_stop':
      Haptics.selectionAsync();    // soft tap
      return;

    case 'answer_ready':
      // Double tap via expo-haptics; spacing via setTimeout (the actual ms values come from CONFIG.HEARTBEAT_ANSWER_READY).
      Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Medium);
      setTimeout(() => Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Medium),
        CONFIG.HEARTBEAT_ANSWER_READY[0] + CONFIG.HEARTBEAT_ANSWER_READY[1]);
      return;

    case 'error':
      // Long soft pulse — use Vibration API directly via library, or impact + brief hold.
      // expo-haptics doesn't expose duration; for iOS use CHHapticEngine via the second library; Android falls through to a simple notification haptic.
      if (Platform.OS === 'ios') {
        ReactNativeHapticFeedback.trigger('notificationWarning');  // closest built-in to a soft long pulse
      } else {
        // Android: direct Vibrator pattern
        ReactNativeHapticFeedback.trigger('impactMedium');
      }
      return;

    case 'thinking_start':
      // Repeating pulse: 200ms on / 400ms off. Use setInterval to schedule impacts.
      // Initial tick immediate.
      Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Light);
      thinkingTimer = setInterval(() => {
        Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Light);
      }, CONFIG.HEARTBEAT_THINKING_ON_MS + CONFIG.HEARTBEAT_THINKING_OFF_MS);
      return;

    case 'thinking_stop':
      // already cleared above
      return;
  }
}

export function stop(): void {
  clearThinking();
}
```

**Honest note on the rhythmic pulse:** `expo-haptics` only exposes one-shot impacts (no native CHHapticEngine pattern player). The `setInterval` approach above is "good enough" — the *on* phase is felt as the impact (instant), the *off* phase is the gap between intervals. For a more authentic rhythmic feel on iOS, switch to `react-native-haptic-feedback`'s CHHapticEngine API or directly use Apple's AHAP pattern JSON. **If AC1.6.5 (no silent gaps >250ms perception test) fails with setInterval**, the dev agent escalates to AHAP. Story estimate (L) budgets for this iteration.

## 8. Risks

- **iOS CHHapticEngine via `setInterval` may not produce authentic rhythmic feel.** Story estimate L explicitly budgets for an escalation to AHAP patterns if AC1.6.5 fails the perception test.
- **Android phones with weak vibration motors (cheap devices) may make patterns hard to distinguish.** V4 (dad's phone model) catches it. Mitigation: keep all `MS` values config-tunable so sideload-time adjustment is possible.
- **`react-native-haptic-feedback` New Architecture compat.** Library got a 2026 rewrite — verify NewArch turbo-module status against the README at impl time. If broken on RN 0.85, fall back to pure `expo-haptics` and document the degradation.
- **DND respect:** AC5.3 says `answer_ready` fires regardless of DND. iOS treats user-initiated impacts as bypassing DND by default; verify on actual device.
