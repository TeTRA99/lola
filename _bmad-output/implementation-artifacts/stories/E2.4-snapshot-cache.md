# E2.4 — Repeat / extend snapshot-cache layer

> **User story:** As dad, I want to ask Lola to repeat or expand on what she just said, so that I don't have to point the camera again.

## 1. Context

DescribeService (E2.2) already keeps `lastDescribe` as a module-local var (just narration + uri). That's enough for the immediate "repeat" case **if** the URI still exists on disk. This story builds the proper LRU-backed cache so URIs survive across multiple Describe calls and old captures get evicted.

Cache scope: snapshots only. Catalog reference images (E4.3) live in a separate `catalog/` directory and aren't touched by LRU eviction.

## 4. Technical Approach

### 4.1 Module shape

`app/src/services/SnapshotCache.ts`:

```typescript
import { Directory, File, Paths } from 'expo-file-system';
import { CONFIG } from '@/config';

const DIR = new Directory(Paths.document, 'snapshots');

export type SnapshotEntry = {
  uri: string;
  sizeBytes: number;
  savedAt: number;
  narration?: string;
};

const entries: Map<string, SnapshotEntry> = new Map();
let totalBytes = 0;

function ensureDir(): void {
  if (!DIR.exists) DIR.create({ intermediates: true });
}

function evictIfNeeded(): void {
  while (
    entries.size > CONFIG.CACHE_MAX_SNAPSHOTS ||
    totalBytes > CONFIG.CACHE_MAX_BYTES
  ) {
    const oldestUri = entries.keys().next().value;  // Map preserves insertion order
    if (!oldestUri) break;
    const entry = entries.get(oldestUri);
    if (entry) {
      totalBytes -= entry.sizeBytes;
      try { new File(oldestUri).delete(); } catch { /* file already gone */ }
    }
    entries.delete(oldestUri);
  }
}

export async function saveSnapshot(base64: string): Promise<string> {
  ensureDir();
  const ts = Date.now();
  const file = new File(DIR, `${ts}.jpg`);
  // base64 → bytes → write. expo-file-system File supports writing base64 directly.
  file.write(base64, { encoding: 'base64' });
  const sizeBytes = file.size ?? Math.floor((base64.length * 3) / 4);  // approx if size unavailable
  const entry: SnapshotEntry = { uri: file.uri, sizeBytes, savedAt: ts };
  entries.set(file.uri, entry);
  totalBytes += sizeBytes;
  evictIfNeeded();
  return file.uri;
}

export function getEntry(uri: string): SnapshotEntry | null {
  return entries.get(uri) ?? null;
}

export function getLatest(): SnapshotEntry | null {
  let latest: SnapshotEntry | null = null;
  for (const e of entries.values()) {
    if (!latest || e.savedAt > latest.savedAt) latest = e;
  }
  return latest;
}

export function attachNarration(uri: string, narration: string): void {
  const e = entries.get(uri);
  if (e) e.narration = narration;
}

export function _resetForTests(): void {
  for (const uri of entries.keys()) {
    try { new File(uri).delete(); } catch { /* ignore */ }
  }
  entries.clear();
  totalBytes = 0;
}
```

### 4.2 DescribeService integration

In `DescribeService.run()`, replace the `lastDescribe` module-local pattern with cache writes:

```typescript
import * as SnapshotCache from '@/services/SnapshotCache';
// ... after successful response ...
const persistedUri = await SnapshotCache.saveSnapshot(snap.value.base64);
SnapshotCache.attachNarration(persistedUri, narration);
// lastDescribe is now derivable from SnapshotCache.getLatest()
// — drop the module-local var; replace getLastDescribe() with a thin wrapper:
```

```typescript
export function getLastDescribe(): { narration: string; snapshotUri: string } | null {
  const e = SnapshotCache.getLatest();
  if (!e || !e.narration) return null;
  return { narration: e.narration, snapshotUri: e.uri };
}
```

## 7. Risks

- **expo-file-system new-API churn:** `File.write({ encoding: 'base64' })` signature may differ from what the spec assumes; verify against `node_modules/expo-file-system/build/File.d.ts` at impl time. Fall back to `File.writeAsync` if sync write isn't available.
- **base64 size estimation:** if `file.size` isn't populated synchronously after write, use `Math.floor((base64.length * 3) / 4)` as approximation. ~6% error, doesn't matter for LRU bounds.
- **Cold-restart eviction** (no persistence of the index): acceptable per AC2.4.4. If a future story needs cross-session repeat, add SQLite-backed metadata then.
