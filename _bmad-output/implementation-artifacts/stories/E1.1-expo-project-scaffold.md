# E1.1 — Expo project scaffold + EAS config

> **User story:** As Charly, I want a fresh Expo SDK 56 project with EAS configured for both Android and iOS, so that I have a working build pipeline before writing any feature code.

## 1. Context

This is the **first** dev story of the Lola v0.9 build. Everything else in E1 (and downstream) depends on the scaffold this story produces. When this story closes, the project tree exists, has the SDK 56 + RN 0.85 baseline pinned, has EAS configured for both platforms, has the source-layer directory structure ready, and has `src/config.ts` populated with every architecture-locked constant so subsequent stories can `import { CONFIG } from '@/config'` without re-deciding values.

This story does **not** implement any feature behavior. No camera capture, no TTS, no SQLite work — those are E1.3, E1.5, E1.7. This is pure scaffolding.

### 4.2 Scaffold commands

Run from project root:

```bash
# 1. Create the Expo app — blank-typescript template (NOT default; default uses expo-router)
npx create-expo-app@latest app --template blank-typescript

# 2. Lock to SDK 56 patch series
cd app
npm install expo@~56.0.5

# 3. Initialize EAS  (the CLI is invoked via `npx eas`, NOT `npx eas-cli`)
npx eas login                    # one-time per machine
npx eas init                     # links project to EAS, generates eas.json scaffold
npx eas build:configure          # ensures android/ios platform config exists

# 4. Verify the install
npx expo-doctor
```

### 4.4 Path alias `@/*` — type-time + runtime

**Two pieces required** — TypeScript alone is type-time only; Metro needs its own runtime resolver.

**(a) Type-time** — `app/tsconfig.json`:
```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": { "@/*": ["src/*"] }
  }
}
```

**(b) Runtime** — install the resolver:
```bash
cd app
npm install --save-dev babel-plugin-module-resolver
```

And `app/babel.config.js`:
```js
module.exports = function(api) {
  api.cache(true);
  return {
    presets: ['babel-preset-expo'],
    plugins: [
      ['module-resolver', { alias: { '@': './src' } }]
    ]
  };
};
```

Both pieces are tested by AC1.1.10 (type-check) and AC1.1.11 (runtime boot). Subsequent stories use `import { CONFIG } from '@/config'`.

## 6. `app/src/config.ts` — Verbatim from Architecture §11

```typescript
export const CONFIG = {
  // Model + gateway (NFR-11, AD-4)
  MODEL_ID: 'google/gemini-2.5-flash',
  MODEL_ID_CHEAP: 'google/gemini-2.5-flash-lite',  // cost-A/B toggle
  GATEWAY_BASE_URL: 'https://openrouter.ai/api/v1',

  // Locale + speech (NFR-4, NFR-9)
  TTS_LOCALE: 'es-AR',
  TTS_LOCALE_FALLBACKS: ['es-419', 'es-MX'] as const,
  TTS_RATE: 0.85,
  STT_LOCALE: 'es-AR',
  STT_LOCALE_FALLBACKS: ['es-419', 'es-MX'] as const,
  STT_END_OF_SPEECH_MS: 1200,
  STT_HARD_CAP_MS: 10000,

  // Vision + confidence
  CONFIDENCE_THRESHOLD: 0.70,

  // Snapshot cache (AD-5)
  CACHE_MAX_SNAPSHOTS: 50,
  CACHE_MAX_BYTES: 200 * 1024 * 1024,

  // Memory freshness (NFR-8, AD-3)
  MEMORY_FRESH_HOURS: 24,
  MEMORY_HEDGE_HOURS: 72,

  // Heartbeat haptic patterns (FR-5)
  HEARTBEAT_LOOKING_MS: 50,
  HEARTBEAT_THINKING_ON_MS: 200,
  HEARTBEAT_THINKING_OFF_MS: 400,
  HEARTBEAT_ANSWER_READY: [50, 100, 50] as const,
  HEARTBEAT_ERROR_MS: 600,

  // Hidden setup gestures (FR-3, AD-6)
  SETUP_GESTURE_HOLD_MS: 5000,
  DEBUG_GESTURE_HOLD_MS: 10000,
};

export type Config = typeof CONFIG;
```

**Note on `as const`:** Applied to the *array* values (`HEARTBEAT_ANSWER_READY`, `TTS_LOCALE_FALLBACKS`, `STT_LOCALE_FALLBACKS`) where readonly + literal types are meaningful. Deliberately **not** applied to the object as a whole — that would make every number a literal type (`MEMORY_FRESH_HOURS: 24` becomes type `24` instead of `number`), forcing widening casts everywhere downstream.

## 8. Dependencies & Blockers

- **Depends on:** Nothing. This is the first dev story.
- **Pre-Sprint validation results (V1–V4) are NOT a blocker** for this story — `config.ts` carries placeholders that may be tuned by later stories once V3/V4 land. ## 9. Risks

- **`npx create-expo-app` template churn:** Expo's templates evolve patch-to-patch. If the generated `app.json` or `package.json` deviates from this story's assumptions, treat the story's spec as authoritative — patch the generated files to match.
- **Template confusion (blank-typescript vs default):** the `default` template uses expo-router (filesystem routing) — this project does **not**. Always re-run with `--template blank-typescript`. If a future contributor regenerates, they must repeat the right invocation.
- **EAS first-time login:** `eas login` requires an Expo account. If Charly doesn't have one, create at expo.dev — free tier sufficient for MVP.
- **Apple Dev account state (carried from Pre-Sprint):** doesn't block E1.1 — iOS production builds happen at E6.2. iOS development builds work without enrollment (use simulator + free signing on Charly's own device for 7-day windows).
