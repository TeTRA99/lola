# E1.7 — SQLite migrations + schema v1

> **User story:** As a developer, I want the SQLite schema from architecture §3 AD-3 created on first run, so that every other service can read/write without bootstrapping the DB itself.

## 1. Context

Three tables back the v0.9 data model: `objects` (FR-3 catalog), `sightings` (FR-4 byproduct memory), `usage_events` (AD-6 telemetry). They land all at once in schema v1; future schema versions arrive as needed via `PRAGMA user_version` migrations.

## 3. Acceptance Criteria

- [ ] **AC1.7.1** — `app/src/adapters/storage.ts` exports `getDb(): Promise<SQLiteDatabase>` (returns a singleton) and re-exports `SQLiteProvider` + `useSQLiteContext` from `expo-sqlite` for component-tree consumers.
- [ ] **AC1.7.2** — Schema v1 = the three tables exactly as in architecture AD-3:
  - `objects` (id, canonical_name UNIQUE, display_name, description NULLABLE, source, reference_image_uri NULLABLE, created_at, updated_at)
  - `sightings` (id, object_id FK CASCADE, observed_at, snapshot_uri NULLABLE, room_hint NULLABLE, source_action, excerpt) + `idx_sightings_recent`
  - `usage_events` (id, occurred_at, action, success, latency_ms NULLABLE, error_kind NULLABLE)
- [ ] **AC1.7.3** — Schema creation is guarded by `PRAGMA user_version = 1`. Re-launching the app does **not** re-run CREATE TABLE statements (idempotent).
- [ ] **AC1.7.4** — A migration framework in `app/src/adapters/migrations/` allows incrementing `user_version` for schema v2+. v0.9 only has v1; the framework should accept future migrations cleanly.
- [ ] **AC1.7.5** — Unit test `app/src/adapters/__tests__/storage.test.ts` opens an in-memory DB, runs migrations, asserts all three tables exist with the documented columns + index, and verifies that inserting + selecting works end-to-end on each table.
- [ ] **AC1.7.6** — A foreign-key cascade test: deleting an `objects` row removes its `sightings` rows.
- [ ] **AC1.7.7** — All write paths use prepared statements / parameterized queries (no string concatenation). Even though this is a single-user local app with no untrusted input, the discipline protects against accidental SQL injection if a future story feeds in arbitrary text.

## 4. Technical Approach

### 4.1 Install

### 4.2 Schema file

`app/src/adapters/migrations/v1.sql`:

```sql
CREATE TABLE objects (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  canonical_name TEXT NOT NULL UNIQUE,
  display_name TEXT NOT NULL,
  description TEXT,
  source TEXT NOT NULL,
  reference_image_uri TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE sightings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  object_id INTEGER NOT NULL REFERENCES objects(id) ON DELETE CASCADE,
  observed_at INTEGER NOT NULL,
  snapshot_uri TEXT,
  room_hint TEXT,
  source_action TEXT NOT NULL,
  excerpt TEXT
);

CREATE INDEX idx_sightings_recent ON sightings(object_id, observed_at DESC);

CREATE TABLE usage_events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  occurred_at INTEGER NOT NULL,
  action TEXT NOT NULL,
  success INTEGER NOT NULL,
  latency_ms INTEGER,
  error_kind TEXT
);
```

### 4.3 Migration runner

`app/src/adapters/storage.ts`:

```typescript
import * as SQLite from 'expo-sqlite';

let db: SQLite.SQLiteDatabase | null = null;
const DB_NAME = 'lola.db';
const TARGET_VERSION = 1;

const V1_SQL = `
  PRAGMA foreign_keys = ON;
  CREATE TABLE objects (...);
  CREATE TABLE sightings (...);
  CREATE INDEX idx_sightings_recent ...;
  CREATE TABLE usage_events (...);
  PRAGMA user_version = 1;
`;

async function migrate(d: SQLite.SQLiteDatabase): Promise<void> {
  const row = await d.getFirstAsync<{ user_version: number }>('PRAGMA user_version;');
  const current = row?.user_version ?? 0;
  if (current >= TARGET_VERSION) return;
  if (current === 0) await d.execAsync(V1_SQL);
  // Future: if (current < 2) await d.execAsync(V2_SQL); etc.
}

export async function getDb(): Promise<SQLite.SQLiteDatabase> {
  if (db) return db;
  db = await SQLite.openDatabaseAsync(DB_NAME);
  await migrate(db);
  return db;
}

export { SQLiteProvider, useSQLiteContext } from 'expo-sqlite';
```

(Use `SQLiteProvider` at the app root for hook-based consumers; use `getDb()` for service-layer code that runs outside the React tree.)

### 4.4 App root wiring

`app/src/app.tsx` wraps the tree:

```tsx
import { SQLiteProvider } from '@/adapters/storage';

export default function App() {
  return (
    <SQLiteProvider databaseName="lola.db" onInit={migrate}>
      {/* LaunchSplash / HomeScreen tree */}
    </SQLiteProvider>
  );
}
```

(The `onInit` hook is provided by `expo-sqlite`'s SQLiteProvider; references the same `migrate` function from §4.3.)

### 4.5 Foreign-key enforcement

`PRAGMA foreign_keys = ON` must be set per-connection. The migration runner sets it on each `openDatabaseAsync` call.

## 8. Risks

- **`expo-sqlite` async API in SDK 56** — verify against current docs. The `useSQLiteContext` hook + `openDatabaseAsync` are the modern API; older sync `openDatabase` is deprecated.
- **Concurrent open()s** during fast-refresh dev cycles can leave stale connections. Mitigation: the `db` singleton + idempotent migration handles re-opens; the dev tool may complain but production runtime is fine.
- **No backup/restore in v0.9.** If dad's phone wipes, the catalog and sightings are gone. NFR-5 says no cloud sync; this is the cost of privacy-first design. Acceptable for MVP; flag for v1.0 review.
