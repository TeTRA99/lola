# E3.1 — Utterance router

> **As a developer,** I want a single router that classifies an STT result into `repeat`, `extend`, `memory_recall`, or `model_call`, so that AskService stays simple and the routing logic is unit-testable in isolation.

## 1. Context

The Ask flow has four possible interpretations of dad's utterance: repeat-last-describe, extend-with-more-detail, memory-recall ("¿dónde está X?"), and the default model-call path. Centralising this classification in a pure function keeps AskService (E3.2) thin and gives us a fast, exhaustive unit-test surface.

## 3. Acceptance Criteria

- [ ] **AC3.1.1** — `app/src/services/UtteranceRouter.ts` exports `route(utterance: string): RouteDecision`.
  ```ts
  type RouteDecision =
    | { type: 'repeat' }
    | { type: 'extend' }
    | { type: 'memory'; object: string }   // extracted noun
    | { type: 'model' };
  ```
- [ ] **AC3.1.2** — Patterns tolerate optional leading `"Lola,"`, optional inverted `¿`, optional trailing `?`, and surrounding whitespace.
- [ ] **AC3.1.3** — Repeat triggers: utterances matching `(otra vez|de nuevo|repetí)` route to `repeat`.
- [ ] **AC3.1.4** — Extend triggers: utterances matching `(contame más|seguí|más detalle)` route to `extend`.
- [ ] **AC3.1.5** — Memory triggers: utterances matching `(¿?dónde está|¿?viste mi|¿?dónde puse) <noun>` route to `{ type: 'memory', object: <noun> }`. The noun is whatever follows the trigger, trimmed and `?`-stripped.
- [ ] **AC3.1.6** — Everything else routes to `model`.
- [ ] **AC3.1.7** — Order of pattern matching: repeat → extend → memory → model. The first match wins (e.g. `"otra vez ¿dónde está mi cepillo?"` is repeat, not memory).
- [ ] **AC3.1.8** — Unit tests cover ≥10 fixture utterances per branch, including voseo phrasing, missing inverted `¿`, mixed casing, and the precedence ordering.

## 4. Technical Approach

`app/src/services/UtteranceRouter.ts`:

```typescript
export type RouteDecision =
  | { type: 'repeat' }
  | { type: 'extend' }
  | { type: 'memory'; object: string }
  | { type: 'model' };

// Strip a leading "Lola," and whitespace, then optionally strip leading ¿.
function normalize(raw: string): string {
  return raw.trim().replace(/^lola[,\s]+/i, '').trim();
}

const REPEAT_RE = /(otra vez|de nuevo|repet[ií])/i;
const EXTEND_RE = /(contame m[áa]s|segu[íi]|m[áa]s detalle)/i;
const MEMORY_RE = /\¿?(d[óo]nde est[áa]|viste mi|d[óo]nde puse)\s+(.+?)\??$/i;

export function route(utterance: string): RouteDecision {
  const s = normalize(utterance);
  if (REPEAT_RE.test(s)) return { type: 'repeat' };
  if (EXTEND_RE.test(s)) return { type: 'extend' };
  const m = MEMORY_RE.exec(s);
  if (m && m[2]) return { type: 'memory', object: m[2].trim().replace(/\?+$/, '') };
  return { type: 'model' };
}
```

## 7. Risks

- **Argentine accent variations** — dad's actual phrasing may not match the fixed regex set. Mitigation: V3 STT fixture in `docs/validation/stt-fixture.md` doubles as a router test set; if real utterances miss the patterns, add them. Cheap to extend.
- **Memory-trigger noun extraction is greedy** — `"¿dónde está mi cepillo de dientes?"` extracts `mi cepillo de dientes` which is correct. But `"¿dónde está mi cepillo, lo perdí?"` extracts the whole tail including the comma clause. Acceptable for v0.9; refine if dad speaks compound questions.
