# E4.1 — LaunchSplash 5-second hold gesture

> **As Charly,** I want a hidden way into the setup screen from the splash, so that dad can never accidentally reach it.

## 1. Context

The FR-3 setup screen is Charly-only — dad must never reach it. v0.9 hides it behind a long-press gesture on the splash logo. Same gesture pattern (different duration) gates the DebugScreen in E6.4.

The existing `src/screens/LaunchSplash.tsx` (from E1.3) auto-dismisses after 800ms. This story adds the long-press detection without disrupting the auto-dismiss for the normal cold-launch flow.

## 3. Acceptance Criteria

- [ ] **AC4.1.1** — Sustained press on the Lola logo for ≥`CONFIG.SETUP_GESTURE_HOLD_MS` (5000) calls `onSetup` callback prop. Any release before 5s → normal splash auto-dismiss continues.
- [ ] **AC4.1.2** — A sustained press of ≥`CONFIG.DEBUG_GESTURE_HOLD_MS` (10000) calls `onDebug` callback prop. Hand-off at 5s is clean — `onSetup` does NOT also fire when the user crosses 10s without releasing.
- [ ] **AC4.1.3** — Tap-and-release (under 5s) does nothing special; auto-dismiss fires at 800ms as in E1.3.
- [ ] **AC4.1.4** — `LaunchSplash` props: `onDone` (existing), `onSetup?`, `onDebug?` — both optional. If callbacks aren't provided, the gesture is silently no-op.
- [ ] **AC4.1.5** — Auto-dismiss is **suspended while the press is active** — if Charly's mid-hold at the 800ms mark, the splash doesn't disappear under his finger.
- [ ] **AC4.1.6** — Manual test on iOS dev client: tap shows greeting + dismiss; 5-sec hold opens SetupScreen placeholder; 10-sec hold opens DebugScreen placeholder.

## 4. Technical Approach

### 4.1 Gesture timer state machine

```typescript
import { useEffect, useRef, useState } from 'react';
import { Pressable, StyleSheet, Text, View } from 'react-native';
import { speak } from '@/adapters/tts';
import { COPY, CONFIG } from '@/services';

const SPLASH_DURATION_MS = 800;

type Props = {
  onDone: () => void;
  onSetup?: () => void;
  onDebug?: () => void;
};

export function LaunchSplash({ onDone, onSetup, onDebug }: Props) {
  const [pressed, setPressed] = useState(false);
  const autoDismiss = useRef<ReturnType<typeof setTimeout> | null>(null);
  const setupTimer = useRef<ReturnType<typeof setTimeout> | null>(null);
  const debugTimer = useRef<ReturnType<typeof setTimeout> | null>(null);
  const fired = useRef<'none' | 'setup' | 'debug'>('none');

  // Greeting + auto-dismiss on mount (when not held).
  useEffect(() => {
    void speak(COPY.greeting);
    return () => {
      [autoDismiss, setupTimer, debugTimer].forEach(t => {
        if (t.current) clearTimeout(t.current);
      });
    };
  }, []);

  useEffect(() => {
    if (pressed) {
      // Cancel auto-dismiss while held.
      if (autoDismiss.current) { clearTimeout(autoDismiss.current); autoDismiss.current = null; }
      fired.current = 'none';
      setupTimer.current = setTimeout(() => {
        if (fired.current === 'none') {
          fired.current = 'setup';
          // setup timer doesn't fire onSetup yet — wait for release in case Charly holds past 10s.
        }
      }, CONFIG.SETUP_GESTURE_HOLD_MS);
      debugTimer.current = setTimeout(() => {
        fired.current = 'debug';
      }, CONFIG.DEBUG_GESTURE_HOLD_MS);
    } else {
      // Release: fire whichever stage we hit, OR resume auto-dismiss if nothing.
      if (setupTimer.current) { clearTimeout(setupTimer.current); setupTimer.current = null; }
      if (debugTimer.current) { clearTimeout(debugTimer.current); debugTimer.current = null; }
      if (fired.current === 'debug') {
        onDebug?.();
      } else if (fired.current === 'setup') {
        onSetup?.();
      } else if (!autoDismiss.current) {
        autoDismiss.current = setTimeout(onDone, SPLASH_DURATION_MS);
      }
      fired.current = 'none';
    }
  }, [pressed, onSetup, onDebug, onDone]);

  return (
    <Pressable
      onPressIn={() => setPressed(true)}
      onPressOut={() => setPressed(false)}
      style={styles.root}
    >
      <Text style={styles.brand}>Lola</Text>
    </Pressable>
  );
}
```

**Why fire on release, not at the threshold itself:** Charly might intend to reach DebugScreen (10s) but the 5s `setup` would also have triggered halfway through. By deferring the action to release, the *highest* threshold crossed wins. Cleaner UX, single decision point.

### 4.2 App wiring

`src/app.tsx`:

```typescript
const [screen, setScreen] = useState<'splash' | 'home' | 'setup' | 'debug'>('splash');

return (
  <SQLiteProvider databaseName="lola.db" onInit={migrate}>
    {screen === 'splash' && (
      <LaunchSplash
        onDone={() => setScreen('home')}
        onSetup={() => setScreen('setup')}
        onDebug={() => setScreen('debug')}
      />
    )}
    {screen === 'home' && <HomeScreen />}
    {screen === 'setup' && <SetupScreen onClose={() => setScreen('home')} />}
    {screen === 'debug' && <DebugScreen onClose={() => setScreen('home')} />}
  </SQLiteProvider>
);
```

## 7. Risks

- **No component test** — long-press gesture testing without `@testing-library/react-native` requires Detox or manual. Verified manually.
- **Press-during-greeting:** speak() is fire-and-forget, so the greeting may finish before Charly's 5s elapses. That's fine — auditory artefact only, no functional issue.
- **Accidental long-press by dad:** the whole point is unreachability. AC3.1 mitigation = manual test by handing dad the unlocked app for 60s and confirming he doesn't trip the gesture.
