# E2.2 — DescribeService orchestration

> **User story:** As dad, I want pressing the top button to result in a short Argentine-Spanish description of what's in front of me, so that I know what I'm looking at without asking anyone.

## 1. Context

The first dad-facing behavior with substance. DescribeService is the orchestrator that ties together camera (E1.5) + OpenRouter (E2.1) + TTS (E1.3) + haptic state machine (E1.6) + memory log (eventually E5.1).

This story focuses on the **service-level orchestration logic**. The actual button in HomeScreen lands in E2.3; this story can be exercised via a debug button in `__DEV__`.

## 3. Acceptance Criteria

- [ ] **AC2.2.1** — `DescribeService.run()` returns `Promise<Result<DescribeOutcome, DescribeError>>` per the E1.8 skeleton signature. Orchestrates: heartbeat `looking` → camera snapshot → heartbeat `thinking` → OpenRouter chat → heartbeat `answer_ready` → TTS speak → cache snapshot for repeat/extend (E2.4 builds the cache; for E2.2 a simple in-memory `lastDescribe` variable is fine).
- [ ] **AC2.2.2** — Snapshot uses `captureSnapshot()` from E1.5. If returns `err('permission_denied')`, the service calls TTS with `COPY.errors.cameraPermission` and returns the corresponding `DescribeError`. (AC1.5.4 maps for us.)
- [ ] **AC2.2.3** — OpenRouter call uses `chat({ systemPrompt: buildSystemPrompt(catalog), userText: 'Describe esta escena.', imageBase64 })`. Catalog comes from `OnboardingService.getCatalog()` — but E4.4 hasn't shipped yet, so for E2.2 we wrap that call in a try/catch that returns `null` (the prompt handles null catalog gracefully).
- [ ] **AC2.2.4** — Low-confidence detection: if Gateway returns `ok` with `objects: []` AND narration starts with one of the gentle-question prefixes (`No estoy segura`, `No tengo`), treat as `DescribeError.low_confidence` AT THE OUTCOME LEVEL — still narrate (TTS speaks the gentle question) but track it for telemetry. This is per FR-1's confidence-handling spec.
- [ ] **AC2.2.5** — Network error path: `chat` returns `err('network')` → call TTS with `COPY.errors.noNetwork`, transition heartbeat to `error`, resolve with `err('network')`.
- [ ] **AC2.2.6** — Heartbeat transitions are contiguous — between any two transitions, no silent gap >250ms (per architecture §4.3, enforced via state machine: every transition fires immediately when the previous step's `await` resolves; no intervening sync work).
- [ ] **AC2.2.7** — Last successful outcome is cached in module-local state: `getLastDescribe(): { narration: string; snapshotUri: string } | null`. Used by E2.4 (proper LRU cache) and the repeat trigger in E3.1 (utterance router).
- [ ] **AC2.2.8** — Telemetry: on each `run()` completion, write a row to `usage_events` via the SQLite db (E1.7's `getDb()`) — `{ occurred_at: now, action: 'describe', success: ok ? 1 : 0, latency_ms, error_kind: err.error ?? null }`.
- [ ] **AC2.2.9** — Unit tests (Jest) mock camera, gateway, TTS, haptics, storage. Verify: (a) happy path produces TTS call with the narration; (b) `permission_denied` path produces TTS call with `COPY.errors.cameraPermission`; (c) `network` path produces TTS call with `COPY.errors.noNetwork` and heartbeat `error`; (d) `low_confidence` path produces TTS call with the gentle-question narration and outcome `err('low_confidence')`; (e) `usage_events` row is written on every path.

## 4. Technical Approach

### 4.1 Service implementation

`app/src/services/DescribeService.ts` (replaces the E1.8 skeleton):

```typescript
import { speak } from '@/adapters/tts';
import { fire } from '@/adapters/haptics';
import { captureSnapshot } from '@/adapters/camera';
import { chat } from '@/gateways/openrouter';
import { buildSystemPrompt } from '@/prompts/lola';
import { getDb } from '@/adapters/storage';
import { COPY } from '@/services/CopyModule';
import * as OnboardingService from '@/services/OnboardingService';
import { ok, err, type Result } from '@/utils/result';
import { now } from '@/utils/time';

export type DescribeError = 'permission_denied' | 'no_camera' | 'low_confidence' | 'network' | 'parse_fail' | 'unknown';

export type DescribedObject = { canonical: string; display: string; room_hint: string | null };
export type DescribeOutcome = { narration: string; objects: DescribedObject[]; snapshotUri: string };

let lastDescribe: { narration: string; snapshotUri: string } | null = null;

const LOW_CONFIDENCE_PREFIXES = ['No estoy segura', 'No tengo', 'No puedo'];

async function loadCatalogSafe() {
  try { return await OnboardingService.getCatalog(); }
  catch { return null; }
}

async function logEvent(action: 'describe', success: boolean, latency_ms: number, error_kind: string | null) {
  try {
    const db = await getDb();
    await db.runAsync(
      'INSERT INTO usage_events (occurred_at, action, success, latency_ms, error_kind) VALUES (?, ?, ?, ?, ?)',
      [now(), action, success ? 1 : 0, latency_ms, error_kind],
    );
  } catch { /* telemetry failure is silent */ }
}

export async function run(): Promise<Result<DescribeOutcome, DescribeError>> {
  const t0 = now();
  fire('looking');

  // 1. Snapshot
  const snap = await captureSnapshot();
  if (!snap.ok) {
    fire('error');
    const msg = snap.error === 'permission_denied' ? COPY.errors.cameraPermission : COPY.errors.generic;
    await speak(msg);
    await logEvent('describe', false, now() - t0, snap.error);
    return err(snap.error === 'permission_denied' ? 'permission_denied' : 'no_camera');
  }

  // 2. Model call
  fire('thinking_start');
  const catalog = await loadCatalogSafe();
  const resp = await chat({
    systemPrompt: buildSystemPrompt(catalog),
    userText: 'Describe esta escena.',
    imageBase64: snap.value.base64,
  });
  fire('thinking_stop');

  if (!resp.ok) {
    fire('error');
    const msg = resp.error === 'network' ? COPY.errors.noNetwork : COPY.errors.generic;
    await speak(msg);
    await logEvent('describe', false, now() - t0, resp.error);
    return err(resp.error === 'network' ? 'network' : resp.error === 'parse_fail' ? 'parse_fail' : 'unknown');
  }

  // 3. Low-confidence detection
  const { narration, objects } = resp.value;
  const isLowConfidence =
    objects.length === 0 &&
    LOW_CONFIDENCE_PREFIXES.some(p => narration.startsWith(p));

  // 4. Speak (regardless of confidence — even the gentle-question is voiced)
  fire('answer_ready');
  await speak(narration);

  lastDescribe = { narration, snapshotUri: snap.value.uri };

  await logEvent('describe', !isLowConfidence, now() - t0, isLowConfidence ? 'low_confidence' : null);

  if (isLowConfidence) return err('low_confidence');
  return ok({ narration, objects, snapshotUri: snap.value.uri });
}

export function getLastDescribe(): { narration: string; snapshotUri: string } | null {
  return lastDescribe;
}

export function _resetForTests(): void {
  lastDescribe = null;
}
```

**Note on AD-4 catalog injection:** `OnboardingService.getCatalog()` throws `'not_implemented'` until E4.4 lands. `loadCatalogSafe` wrapping it in a try/catch is the bridge — null catalog → prompt without catalog block → still produces valid narration, just less personalized. Once E4.4 lands the null path becomes the empty-catalog path naturally.

### 4.2 Heartbeat state machine

## 8. Risks

- **Catalog dep on E4.4** — degrades gracefully but DescribeService can't reference catalog objects by display name until E4.4 ships. Acceptable for v0.9 dev sequence; if dad's-objects matter in early demos, prioritize E4.4 over E5.x.
- **HeartbeatService skeleton** is just `fire()` — no global state. Cross-service heartbeat state (e.g., AskService starts while DescribeService's TTS is still playing) is unhandled here. Architecture §4.3 implies a global state machine; v0.9 punts on this — adequate because dad doesn't multi-tap fast enough to matter. Revisit if v1.0 observes conflicts.
- **Module-local `lastDescribe`** isn't React-aware. If the JS engine reloads (hot-reload in dev, app process kill in prod), the cache is gone. That's fine — E2.4 builds the persistent cache.
