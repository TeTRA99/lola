## 4. Acceptance Criteria — deep pass

### AC1.1.1 — `expo: ~56.0.5`, `react: 19.2.x`, `react-native: 0.85.x`

**BLOCKER.** Pinning React and React Native versions independently of `expo` is anti-pattern in managed-workflow Expo. SDK 56 dictates React 19.2 and RN 0.85 as transitive deps; over-pinning can cause `expo-doctor` warnings or conflicts. **Fix:** keep `expo: ~56.0.5` as the only explicit pin. Require `npx expo-doctor` to confirm the React/RN versions are correct (which Doctor does automatically). Remove the literal version assertions on React and RN.

### AC1.1.2 — `newArchEnabled: true`

**BLOCKER.** "Or not explicitly set — SDK 56 defaults to on" is ambiguous and untestable. Either:
- (a) Require explicit `"newArchEnabled": true` in `app.json` → testable via `grep`, or
- (b) Don't mention it (rely on SDK default).

**Fix:** go with (a). Defaults can shift in patch releases; explicit is safer for a v0.9 build.

### AC1.1.3 — `eas.json` profiles

**NIT.** Missing the `development` profile's *iOS* `simulator: false` rationale — Charly's iOS device is the dev target, simulator isn't needed. The current `false` is correct but uncommented; a future reader might toggle to `true` "for convenience" and break the device-first dev loop. **Fix:** add a one-line comment in the file (or in this AC) calling out *why* `simulator: false`.

### AC1.1.4 — `expo prebuild --clean`

**BLOCKER.** Managed workflow Expo projects **do not** run `expo prebuild` as part of normal development. `prebuild` is for "bare workflow" or to generate native projects for inspection. Running it on a managed project either:
- (a) Generates native projects on disk (which we then gitignore — wasteful regeneration), or
- (b) Silently does nothing if not configured.

The AC is testing the wrong thing. **Fix:** replace with a more meaningful "scaffold-is-runnable" test:

```
AC1.1.4 — `cd app && npx expo start --no-dev --minify` boots Metro and exits cleanly
without "module not found" or "missing config" errors.
```

### AC1.1.5 — Source layout

**NIT.** The layout includes `src/app.tsx` but `create-expo-app` produces a top-level `App.tsx` (or `app/_layout.tsx` if using expo-router default). Conflict. **Fix:** explicitly call out which template is used. Two clean options:
- (a) Use `--template blank-typescript` (gives a simple `App.tsx`); then move/rename to `src/app.tsx`.
- (b) Use `--template default` (which is expo-router-based as of SDK 53+); then the entry point is `app/_layout.tsx` and the `src/` tree is for non-routing code.

Either is fine, but the spec should pick one. **Recommended:** (a) `blank-typescript`. The two-button UI is too small to justify expo-router's filesystem routing; explicit screen components in `src/screens/` are cleaner for a 4-screen app.

### Coverage gaps

**NIT.** No AC for the `tsconfig.json` `paths` config (§4.4 mentions it but no AC verifies it). **Fix:** add `AC1.1.10 — `tsc --noEmit` resolves `import { CONFIG } from '@/config'` (proves the path alias works).`

## 5. Technical Approach

### §4.2 Scaffold commands

**BLOCKER.** Two issues:

1. `npx create-expo-app@latest app --template default` — as of SDK 53+, `default` is the **expo-router** template. Inconsistent with the `src/screens/` layout that doesn't use expo-router. **Fix:** use `--template blank-typescript` (per AC1.1.5 recommendation).
2. `npx eas-cli@latest login` — wrong package name. The current EAS CLI is `eas-cli` and is invoked via `npx eas` (Expo bundles a shim). **Fix:** `npx eas login` is the correct invocation.

### §4.3 `eas.json` content

**OK** — shape is correct for SDK 56 / EAS Build current schema. `cli.version` and `appVersionSource` both valid.

### §4.4 Path alias

**BLOCKER.** As flagged in AC1.1.11 above. TypeScript path config alone is type-time only. Need Metro/Babel runtime resolution. **Fix:** add explicit setup steps to §4.4:

```bash
npm install --save-dev babel-plugin-module-resolver
```

And `app/babel.config.js`:
```js
module.exports = function(api) {
  api.cache(true);
  return {
    presets: ['babel-preset-expo'],
    plugins: [
      ['module-resolver', { alias: { '@': './src' } }]
    ]
  };
};
```

### §4.5 `.gitignore`

**NIT.** See AC1.1.7. Add `*.tsbuildinfo` and `app/.eas/`.

# Compile-time check via TSC project mode
cd app && npx tsc --noEmit
