# E3.3 — Ask button on HomeScreen

> **As dad,** I want the bottom half of the screen to be a button labeled and iconed for "Ask," so that I can find it the same way I find Describe.

## 1. Context

Replaces the placeholder bottom half of HomeScreen (E2.3) with a real Pressable that dispatches AskService.run(). Mirrors E2.3 for symmetry — same press semantics, same grey-out double-fire protection.

## 2. References

- **PRD:** [FR-2 trigger](../../../planning-artifacts/prds/prd-Lola-2026-05-26/prd.md#fr-2-ask-button), [NFR-3 touch target / contrast](../../../planning-artifacts/prds/prd-Lola-2026-05-26/prd.md#5-non-functional-requirements)

## 3. Acceptance Criteria

- [ ] **AC3.3.1** — Bottom half of HomeScreen is a Pressable, same dimensions as the top Describe button. Contrast inverted (dark face, light text) to visually distinguish from Describe.
- [ ] **AC3.3.2** — Tap dispatches `AskService.run()`. 100ms grey-out anti-double-fire (same as Describe).
- [ ] **AC3.3.3** — Icon = 🎤 (microphone emoji). Label from `COPY.buttons.askLabel`.
- [ ] **AC3.3.4** — `busy` state for each half is independent (tapping Describe doesn't dim Ask, and vice versa). Acceptable since dad can't physically tap both simultaneously, but the state separation prevents UI confusion if a long-running Describe overlaps an Ask attempt.

## 4. Technical Approach

Modify `HomeScreen.tsx` to swap the placeholder bottom for a functioning Pressable. Each button has its own `busy` state.

```typescript
const [busyDesc, setBusyDesc] = useState(false);
const [busyAsk, setBusyAsk] = useState(false);
// ... handler symmetric to E2.3's
```
