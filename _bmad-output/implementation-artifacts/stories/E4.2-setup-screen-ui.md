# E4.2 — SetupScreen UI (English, Charly-facing)

> **As Charly,** I want a clean setup UI in English with the affordances to add, edit, and remove tagged objects, so that I can run this flow efficiently while sitting with dad.

## 1. Context

This is the entry surface Charly uses at sideload time (and any later refresh). All UI strings are English — dad never sees this screen (AC3.1 gate from E4.1's long-press). Catalog persistence is OnboardingService (E4.4); photo capture is E4.3.

## 2. References

- **PRD:** [FR-3 behavior](../../../planning-artifacts/prds/prd-Lola-2026-05-26/prd.md#fr-3-remember-this-for-me-charly-run-one-time), [AC3.4 English-only Charly-facing](../../../planning-artifacts/prds/prd-Lola-2026-05-26/prd.md#fr-3-remember-this-for-me-charly-run-one-time), [AC3.5 <10min for 5 objects](../../../planning-artifacts/prds/prd-Lola-2026-05-26/prd.md#fr-3-remember-this-for-me-charly-run-one-time)

## 3. Acceptance Criteria

- [ ] **AC4.2.1** — `app/src/screens/SetupScreen.tsx` renders a scrollable list of catalog objects (via `OnboardingService.getCatalog()`) with each row showing display name + first photo thumbnail + edit + delete icons.
- [ ] **AC4.2.2** — "Add object" CTA at top (or floating action button) opens an inline sub-flow for capture + naming (delegates to E4.3 for camera; E4.4 for storage).
- [ ] **AC4.2.3** — Edit row opens a modal/sheet with the same form (display name, optional Spanish description, photos), pre-filled.
- [ ] **AC4.2.4** — Delete row prompts a confirmation ("Delete 'tu cepillo'?") in English, then calls `OnboardingService.removeObject(id)`.
- [ ] **AC4.2.5** — "Done" button in header closes the screen via `onClose` prop, returning to HomeScreen.
- [ ] **AC4.2.6** — All UI strings inline (English) — not in COPY. CopyModule is dad-facing only.
- [ ] **AC4.2.7** — Empty-catalog state: friendly message "No tagged objects yet. Tap '+' to add one." (English) + Add button visible.

### 4.3 Component shape

`app/src/screens/SetupScreen.tsx`:

```typescript
import { useEffect, useState } from 'react';
import { FlatList, Pressable, StyleSheet, Text, TextInput, View, Image } from 'react-native';
import * as OnboardingService from '@/services/OnboardingService';
import type { CatalogObject } from '@/services/OnboardingService';

type Mode =
  | { kind: 'list' }
  | { kind: 'add' }
  | { kind: 'edit'; obj: CatalogObject };

export function SetupScreen({ onClose }: { onClose: () => void }) {
  const [catalog, setCatalog] = useState<CatalogObject[]>([]);
  const [mode, setMode] = useState<Mode>({ kind: 'list' });

  const refresh = async () => {
    try { setCatalog(await OnboardingService.getCatalog()); }
    catch { setCatalog([]); }
  };
  useEffect(() => { void refresh(); }, []);

  // ... render list / add-form / edit-form per mode ...
}
```

(Full implementation is more involved but follows from this shape; the dev agent fills in the form fields, photo grid, save handlers calling `OnboardingService.addObject/updateObject/removeObject`. E4.3 provides the capture button.)

## 7. Risks

- **No component tests** — same `@testing-library/react-native` peer conflict. Verified manually + via OnboardingService unit tests (E4.4).
- **Modal / Sheet UX** — React Native doesn't bundle a sheet primitive; use `<Modal>` or a conditional render. v0.9 picks conditional render for simplicity.
- **Photo thumbnail** — `<Image source={{ uri: ref.reference_image_uri }} />` will try to load from the persisted filesystem path. New `Paths.document` URIs work directly; verify on device.
- **AC3.5 (5 objects in <10 min)** is the real test of the UX. If the form is clunky during sideload, iterate on Charly's feedback before v1.0 — v0.9 doesn't need to be perfect, it needs to be usable by Charly.
