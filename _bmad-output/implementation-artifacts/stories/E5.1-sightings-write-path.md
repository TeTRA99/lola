# E5.1 — Sightings write path

> **As a developer,** I want every successful Describe and Ask to write one or more sighting rows, so that the memory log builds passively without a separate user action.

## 1. Context

Architecture's "unfair architecture" claim: Where-is-X (#28) is a free byproduct of Describe + Ask. This story makes the byproduct real by inserting sighting rows on every successful gateway response that mentions objects.

The model's `objects[]` array (E2.1 LolaResponse) already carries `canonical`, `display`, `room_hint`. Each entry becomes a sighting row.

## 2. References

- **PRD:** [FR-4 write path](../../../planning-artifacts/prds/prd-Lola-2026-05-26/prd.md#fr-4-where-is-x-passive-memory-log) (AC4.1), [architecture AD-3 sightings table](../../../planning-artifacts/architecture/architecture-Lola-2026-05-26/architecture.md#ad-3-memory-log-schema--sqlite-two-tables)

## 3. Acceptance Criteria

- [ ] **AC5.1.1** — `MemoryService.recordSighting(input)` inserts a row into the `sightings` table. `input = { canonical, observed_at, snapshot_uri, room_hint, source_action, excerpt }`.
- [ ] **AC5.1.2** — Object resolution: if the canonical matches a `source: 'catalog'` row in `objects`, use that `object_id`. Otherwise INSERT a new row with `source: 'observed'`, then use its id. (Observed-source rows let memory recall track objects dad hasn't tagged.)
- [ ] **AC5.1.3** — DescribeService + AskService model-path call `MemoryService.recordSighting` once per object in the response. Each sighting carries the same `snapshot_uri` (the persisted one from SnapshotCache).
- [ ] **AC5.1.4** — Best-effort: a single sighting write that fails does NOT abort the user-facing flow. Errors are silently swallowed and logged to `usage_events` if convenient.
- [ ] **AC5.1.5** — Returns `Result<{ id: number }, 'storage_error'>` per the E1.8 skeleton signature.
- [ ] **AC5.1.6** — Unit tests cover: known canonical → reuses catalog id; unknown canonical → inserts observed row + sighting; multi-object response → multiple sightings written.

## 4. Technical Approach

`app/src/services/MemoryService.ts` (fills the skeleton's recordSighting + leaves recall stub for E5.2):

```typescript
async function findOrCreateObjectId(canonical: string, display: string): Promise<number | null> {
  const db = await getDb();
  const existing = await db.getFirstAsync<{ id: number }>(
    'SELECT id FROM objects WHERE canonical_name = ?', [canonical],
  );
  if (existing) return existing.id;
  const ts = now();
  try {
    const r = await db.runAsync(
      'INSERT INTO objects (canonical_name, display_name, source, created_at, updated_at) VALUES (?, ?, ?, ?, ?)',
      [canonical, display, 'observed', ts, ts],
    );
    return r.lastInsertRowId;
  } catch { return null; }
}

export async function recordSighting(input: {
  canonical: string;
  display: string;       // needed for observed-source fallback
  observed_at: number;
  snapshot_uri: string | null;
  room_hint: string | null;
  source_action: 'describe' | 'ask';
  excerpt: string | null;
}): Promise<Result<{ id: number }, 'storage_error'>> {
  try {
    const objectId = await findOrCreateObjectId(input.canonical, input.display);
    if (objectId === null) return err('storage_error');
    const db = await getDb();
    const r = await db.runAsync(
      'INSERT INTO sightings (object_id, observed_at, snapshot_uri, room_hint, source_action, excerpt) VALUES (?, ?, ?, ?, ?, ?)',
      [objectId, input.observed_at, input.snapshot_uri, input.room_hint, input.source_action, input.excerpt],
    );
    return ok({ id: r.lastInsertRowId });
  } catch { return err('storage_error'); }
}
```

DescribeService + AskService gain a helper after a successful response:

```typescript
for (const o of resp.value.objects) {
  void MemoryService.recordSighting({
    canonical: o.canonical,
    display: o.display,
    observed_at: now(),
    snapshot_uri: persistedUri,
    room_hint: o.room_hint,
    source_action: 'describe',   // or 'ask'
    excerpt: o.display,
  });
}
```

`void` because sighting failures must not block.

## 6. Risks

- **Many sightings per session** — at 10 sightings/Describe and 5 Describes/day, that's 50 rows/day = 18k/year. SQLite handles millions of rows fine; no concern for v0.9. Add a rolling-window cleanup at v1.0 if needed.
- **`observed_at` collisions** — multiple sightings from one snapshot share a timestamp. Fine; the index on `(object_id, observed_at DESC)` doesn't require uniqueness.
