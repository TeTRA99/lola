# E1.4 — STT adapter + 20-utterance test fixture

> **User story:** As a developer, I want STT plumbing that handles Argentine Spanish reliably enough to detect the FR-2 question shapes, so that dad's "¿qué es esto?" is correctly transcribed.

## 1. Context

STT is one of two voice-side primitives (TTS in E1.3 is the other). E3 (Ask flow) is the consumer — its router classifies transcribed utterances into repeat/extend/memory/model paths. If STT can't reliably hear dad's three core question shapes, the entire Ask flow degrades.

The architecture switched from `@react-native-voice/voice` (archived 2026-01-31) to `expo-speech-recognition` (jamsch) — that fact is locked in [AD-1](../../../planning-artifacts/architecture/architecture-Lola-2026-05-26/architecture.md#ad-1-framework--react-native--expo). This story builds the adapter and the fixture file Charly uses during V3 validation.

- [ ] **AC1.4.5** — Unit test `app/src/adapters/__tests__/stt.test.ts` uses `jest.mock('expo-speech-recognition', () => ({...}))` at module top (required to dodge expo-asset transitive failure under Jest, same pattern as E1.7 storage test). Mocks the imperative event API (`addListener('result' | 'end' | 'error', handler)`) and verifies `listen()` resolves with the final transcript on `end`, resolves with `err('no_speech')` when end fires with empty transcript, and resolves with `err('permission_denied')` when error fires with `code: 'not-allowed'`.
- [ ] **AC1.4.6** — `abort()` causes any in-flight `listen()` to **resolve with `err('timeout')`**. No partial-transcript magic — clean contract.

### 4.2 Adapter shape

`app/src/adapters/stt.ts`:

```typescript
import { ExpoSpeechRecognitionModule } from 'expo-speech-recognition';
import { CONFIG } from '@/config';
import { ok, err, type Result } from '@/utils/result';

export type STTError =
  | 'permission_denied' | 'no_locale' | 'no_speech'
  | 'timeout' | 'engine_unavailable' | 'unknown';
export type ListenOptions = { hardCapMs?: number };

let resolvedLocale: string | null = null;
let activeAbort: (() => void) | null = null;

export function _resetForTests(): void {
  resolvedLocale = null;
  activeAbort = null;
}

async function resolveLocale(): Promise<string | null> {
  if (resolvedLocale) return resolvedLocale;
  try {
    const supported = await ExpoSpeechRecognitionModule.getSupportedLocales();
    const langs = new Set(supported.locales);
    const candidates = [CONFIG.STT_LOCALE, ...CONFIG.STT_LOCALE_FALLBACKS];
    resolvedLocale = candidates.find(loc => langs.has(loc)) ?? null;
    // NOTE: unlike TTS (which falls back to CONFIG.TTS_LOCALE on probe failure),
    // STT *requires* the engine to claim locale support. Failure here returns
    // err('no_locale') from listen() — a degraded "best-effort STT" would
    // produce garbage transcripts.
  } catch {
    resolvedLocale = null;
  }
  return resolvedLocale;
}

export async function listen(opts: ListenOptions = {}): Promise<Result<string, STTError>> {
  const lang = await resolveLocale();
  if (!lang) return err('no_locale');

  const perm = await ExpoSpeechRecognitionModule.requestPermissionsAsync();
  if (!perm.granted) return err('permission_denied');

  return new Promise<Result<string, STTError>>(resolve => {
    let transcript = '';
    let settled = false;
    let hardTimeout: ReturnType<typeof setTimeout> | null = null;

    const settle = (r: Result<string, STTError>) => {
      if (settled) return;
      settled = true;
      if (hardTimeout) clearTimeout(hardTimeout);
      try { ExpoSpeechRecognitionModule.stop(); } catch { /* ignore */ }
      subResult.remove();
      subEnd.remove();
      subError.remove();
      activeAbort = null;
      resolve(r);
    };

    // Imperative listener API (NOT the React hook `useSpeechRecognitionEvent` —
    // that only works inside a component render context).
    const subResult = ExpoSpeechRecognitionModule.addListener('result', (e: { results: { transcript: string }[] }) => {
      if (e.results?.[0]?.transcript) transcript = e.results[0].transcript;
    });
    const subEnd = ExpoSpeechRecognitionModule.addListener('end', () => {
      settle(transcript ? ok(transcript) : err('no_speech'));
    });
    const subError = ExpoSpeechRecognitionModule.addListener('error', (e: { code: string }) => {
      settle(err(e.code === 'not-allowed' ? 'permission_denied' : 'unknown'));
    });

    activeAbort = () => settle(err('timeout'));

    ExpoSpeechRecognitionModule.start({
      lang,
      interimResults: false,
      continuous: false,
    });

    hardTimeout = setTimeout(() => settle(err('timeout')),
      opts.hardCapMs ?? CONFIG.STT_HARD_CAP_MS);
  });
}

export function abort(): void {
  if (activeAbort) activeAbort();
  else { try { ExpoSpeechRecognitionModule.stop(); } catch { /* ignore */ } }
}
```

**Notes on the rewrite** (per validation report blockers):
1. Switched from `useSpeechRecognitionEvent` (React hook — can't run in a Promise constructor) to the imperative `addListener(eventName, handler)` API. This is the call signature actually exposed for non-component contexts.
2. Single `settle()` helper closes over all cleanup state; subscriptions are declared before any handler references them (no temporal-dead-zone use-before-declaration).
3. `abort()` resolves with `err('timeout')` cleanly (per AC1.4.6) and is debounced via the `settled` flag — multiple aborts or a race between abort+end can't double-resolve.

**Library API caveat:** if `expo-speech-recognition` doesn't expose `addListener` directly (some versions only export hooks), the dev agent escalates to a hosting-component pattern (mirror of `CameraHost.tsx` from E1.5). Verify against the installed package's `node_modules/expo-speech-recognition/build/*.d.ts` before writing the production code.

## 8. Risks

- **Locale availability on Android.** Most Google-Speech installs ship `es-AR` but TV-box Androids sometimes don't. V3 catches it; fallback to `es-419` is usually acceptable for Charly's dad's accent.
- **`expo-speech-recognition` API churn.** Library is at v56.0.0 as of 2026-05-17. If event API names differ from this spec, dev agent adapts using the live README; spec is intent-level.
- **Permission UX on first run.** iOS shows the mic + speech-recognition dialogs back-to-back, which can confuse dad. Mitigation: trigger permission request via Charly's setup gesture (E4.1) before dad ever taps Ask, so dialogs are out of the way pre-MVP.
