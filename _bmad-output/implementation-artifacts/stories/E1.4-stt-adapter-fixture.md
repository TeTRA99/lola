# E1.4 — STT adapter + 20-utterance test fixture

> **User story:** As a developer, I want STT plumbing that handles Argentine Spanish reliably enough to detect the FR-2 question shapes, so that dad's "¿qué es esto?" is correctly transcribed.

## 1. Context

STT is one of two voice-side primitives (TTS in E1.3 is the other). E3 (Ask flow) is the consumer — its router classifies transcribed utterances into repeat/extend/memory/model paths. If STT can't reliably hear dad's three core question shapes, the entire Ask flow degrades.

The architecture switched from `@react-native-voice/voice` (archived 2026-01-31) to `expo-speech-recognition` (jamsch) — that fact is locked in [AD-1](../../../planning-artifacts/architecture/architecture-Lola-2026-05-26/architecture.md#ad-1-framework--react-native--expo). This story builds the adapter and the fixture file Charly uses during V3 validation.

### 4.2 Adapter shape

`app/src/adapters/stt.ts`:

```typescript
import {
  ExpoSpeechRecognitionModule,
  useSpeechRecognitionEvent,
} from 'expo-speech-recognition';
import { CONFIG } from '@/config';
import { Result, ok, err } from '@/utils/result';

export type STTError =
  | 'permission_denied' | 'no_locale' | 'no_speech'
  | 'timeout' | 'engine_unavailable' | 'unknown';
export type ListenOptions = { hardCapMs?: number };

let resolvedLocale: string | null = null;

async function resolveLocale(): Promise<string | null> {
  if (resolvedLocale) return resolvedLocale;
  try {
    const supported = await ExpoSpeechRecognitionModule.getSupportedLocales();
    const langs = new Set(supported.locales);
    const candidates = [CONFIG.STT_LOCALE, ...CONFIG.STT_LOCALE_FALLBACKS];
    resolvedLocale = candidates.find(loc => langs.has(loc)) ?? null;
  } catch {
    resolvedLocale = null;
  }
  return resolvedLocale;
}

export async function listen(opts: ListenOptions = {}): Promise<Result<string, STTError>> {
  const lang = await resolveLocale();
  if (!lang) return err('no_locale');

  const perm = await ExpoSpeechRecognitionModule.requestPermissionsAsync();
  if (!perm.granted) return err('permission_denied');

  return new Promise(resolve => {
    let transcript = '';
    let hardTimeout: ReturnType<typeof setTimeout> | null = null;

    const cleanup = () => {
      if (hardTimeout) clearTimeout(hardTimeout);
      ExpoSpeechRecognitionModule.stop();
    };

    ExpoSpeechRecognitionModule.start({
      lang,
      interimResults: false,
      continuous: false,
      // engine will auto-end on CONFIG.STT_END_OF_SPEECH_MS of silence by platform default;
      // hard cap is enforced below
    });

    const subResult = useSpeechRecognitionEvent('result', e => {
      if (e.results && e.results[0]?.transcript) transcript = e.results[0].transcript;
    });
    const subEnd = useSpeechRecognitionEvent('end', () => {
      cleanup();
      subResult.remove(); subEnd.remove(); subError.remove();
      if (!transcript) resolve(err('no_speech'));
      else resolve(ok(transcript));
    });
    const subError = useSpeechRecognitionEvent('error', e => {
      cleanup();
      subResult.remove(); subEnd.remove(); subError.remove();
      resolve(err(e.code === 'not-allowed' ? 'permission_denied' : 'unknown'));
    });

    hardTimeout = setTimeout(() => {
      cleanup();
      resolve(transcript ? ok(transcript) : err('timeout'));
    }, opts.hardCapMs ?? CONFIG.STT_HARD_CAP_MS);
  });
}

export function abort(): void {
  ExpoSpeechRecognitionModule.stop();
}
```

(Note: `useSpeechRecognitionEvent` is a hook in the library docs — verify at impl time whether plain `.addListener` works in this non-component context. If not, refactor to the imperative listener pattern. The story spec records *intent*; the dev agent picks the actual API surface that the library exposes.)

Record each on both **dad's Android** and **Charly's iOS** device. Mark hit (transcribed correctly) or miss.

11. ¿Es esta mi taza?                                  [ ] Android   [ ] iOS
12. ¿Dónde está el remedio de la presión?              [ ] Android   [ ] iOS

13. Hola, ¿cómo estás?                                 [ ] Android   [ ] iOS
14. Gracias, Lola                                      [ ] Android   [ ] iOS
15. No, no es eso                                      [ ] Android   [ ] iOS

## Edge cases (background noise, partial)
16. (whispered) ¿Qué es?                               [ ] Android   [ ] iOS

## 8. Risks

- **Locale availability on Android.** Most Google-Speech installs ship `es-AR` but TV-box Androids sometimes don't. V3 catches it; fallback to `es-419` is usually acceptable for Charly's dad's accent.
- **`expo-speech-recognition` API churn.** Library is at v56.0.0 as of 2026-05-17. If event API names differ from this spec, dev agent adapts using the live README; spec is intent-level.
- **Permission UX on first run.** iOS shows the mic + speech-recognition dialogs back-to-back, which can confuse dad. Mitigation: trigger permission request via Charly's setup gesture (E4.1) before dad ever taps Ask, so dialogs are out of the way pre-MVP.
