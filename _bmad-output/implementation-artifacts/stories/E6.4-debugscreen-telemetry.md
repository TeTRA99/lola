# E6.4 — DebugScreen with usage_events query + export

> **As Charly,** I want a hidden screen that shows the week-2 working / failure-signal metrics from `usage_events`, so that I can measure the NFR-defined outcome without setting up cloud analytics.

## 1. Context

The brief's Success Criteria gates v0.9 on dad-usage thresholds (Describe ≥3×/wk AND Ask ≥3×/wk after week 2). This story exposes the local SQLite `usage_events` data Charly needs to make that call. NFR-5 forbids cloud telemetry — DebugScreen is the local surface.

10-second logo hold gesture (already wired in E4.1) routes here. Currently routes to a placeholder.

## 3. Acceptance Criteria

- [ ] **AC6.4.1** — `DebugScreen.tsx` replaces the placeholder. Header reads "Debug — usage telemetry" in English (Charly-facing).
- [ ] **AC6.4.2** — Shows last 14 days of `usage_events`, grouped by day, with counts per action (`describe`, `ask`). Most-recent first.
- [ ] **AC6.4.3** — Working-signal panel: per-week count of `describe` + `ask` events, with a pass/fail indicator vs the ≥3/wk threshold per action.
- [ ] **AC6.4.4** — Zero-week alert: if any full ISO week in the data has 0 events, flag it loudly (red banner). NFR's failure signal.
- [ ] **AC6.4.5** — Export button copies the entire `usage_events` table as JSON to the clipboard. Tapping shows a confirmation toast.
- [ ] **AC6.4.6** — All UI strings in English (Charly tool). No COPY lookups.
- [ ] **AC6.4.7** — Latest 20 error rows (where `success = 0`) shown at the bottom with timestamp + action + error_kind.

## 4. Technical Approach

`app/src/screens/DebugScreen.tsx`:

```typescript
import { Pressable, ScrollView, StyleSheet, Text, View } from 'react-native';
import * as Clipboard from 'expo-clipboard';
import { useEffect, useState } from 'react';
import { getDb } from '@/adapters/storage';

type Event = { id: number; occurred_at: number; action: string; success: number; latency_ms: number | null; error_kind: string | null };

export function DebugScreen({ onClose }: { onClose: () => void }) {
  const [events, setEvents] = useState<Event[]>([]);
  useEffect(() => { void load(); }, []);

  async function load() {
    const db = await getDb();
    const rows = await db.getAllAsync<Event>(
      `SELECT * FROM usage_events
       WHERE occurred_at > ?
       ORDER BY occurred_at DESC`,
      [Date.now() - 14 * 86400_000],
    );
    setEvents(rows);
  }

  async function exportToClipboard() {
    await Clipboard.setStringAsync(JSON.stringify(events, null, 2));
    // toast or inline confirmation
  }

  // ... compute per-day groupings, per-week counts, error rows ...

  return (
    <ScrollView style={styles.root}>
      <View style={styles.header}>
        <Text style={styles.title}>Debug — usage telemetry</Text>
        <Pressable onPress={onClose}><Text style={styles.close}>Close</Text></Pressable>
      </View>
      {/* working-signal panel, daily counts, error log, export button */}
    </ScrollView>
  );
}
```

Install `expo-clipboard` for the export feature.

## 7. Risks

- **expo-clipboard SDK 56 compat** — verify the import at install. If broken, fall back to a `setSelectionAsync` style or a TextInput rendered + auto-selected.
- **DB query perf** — `usage_events` is unbounded over time. After a year of use it's ~5000 rows. Still fast. Add a `CREATE INDEX idx_usage_recent ON usage_events(occurred_at DESC)` if needed; tracking as a v1.0 polish item.
